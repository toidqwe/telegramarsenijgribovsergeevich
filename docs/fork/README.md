# Старт работы с форком

## Что подготовлено

В `main` импортирован стабильный Telegram Desktop v7.4.1 с исходной историей, лицензиями и закреплёнными зависимостями. Существующий клиент не переписывается. Локальное наличие исходников и успешная проверка метаданных не означают готовую сборку.

## Получить одинаковую основу

Для сборки используйте отдельную папку без пробелов, например `C:\TBuild\tdesktop`. Upstream размещает скачиваемые инструменты и библиотеки рядом с репозиторием; учитывайте значительный расход диска и времени.

```powershell
git clone --recursive https://github.com/toidqwe/telegramarsenijgribovsergeevich.git C:\TBuild\tdesktop
cd C:\TBuild\tdesktop
git remote add upstream https://github.com/telegramdesktop/tdesktop.git
```

Если репозиторий уже клонирован и рабочее дерево чистое:

```powershell
git pull --ff-only origin main
git submodule update --init --recursive
```

Не выполняйте `submodule update --remote`: это меняет договорённую основу. `upstream` автоматически не появляется в новой копии; добавьте его отдельно, если будете заниматься обновлениями.

## Инструменты Windows x64

Требования закреплённого релиза описаны в `../building-win.md`:

- Visual Studio 2026 с Desktop development with C++.
- MSVC **14.44** (v144.4, совместимый с v143), а не только современный toolset по умолчанию.
- Windows SDK **10.0.26100.0** и CMake из Visual Studio.
- Python **3.10** с launcher `py`, Git.

Импортируйте корневой `.vsconfig` через Visual Studio Installer. Это изменение установленных компонентов может требовать прав администратора; скрипты проекта не меняют системную установку самостоятельно. Python 3.10 устанавливается параллельно, не вместо текущего Python.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-repository.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-windows.ps1
```

`Bypass` действует только для запускаемого процесса, а не меняет постоянную политику компьютера. Проверка окружения ничего не устанавливает, не собирает и не авторизует аккаунт; код возврата 1 означает перечисленные недостающие условия.

## Первая локальная Debug-сборка

После успешной проверки окружения:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1 -PrepareLibraries -TestApi
```

`-PrepareLibraries` запускает официальный prepare-скрипт, скачивает и собирает библиотеки. Это длительная операция; не запускайте её параллельно на одном BuildPath. Без флага используются ранее подготовленные библиотеки. `-TestApi` включает официальные публичные TEST ONLY credentials: они не предназначены для распространения или проверки реального входа.

Повторная Debug-сборка:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1 -TestApi
```

Результат после успешной сборки: `out\Debug\Telegram.exe`. Скрипт не запускает приложение и не выполняет вход. Он отключает официальное автообновление и crash reports, чтобы форк не заменился официальным клиентом и не отправлял отчёты в чужую инфраструктуру.

## Собственные API-реквизиты

Получите реквизиты по `../api_credentials.md` для своего приложения. Не присылайте их в чат, не сохраняйте в Git и не используйте реквизиты другого разработчика без договорённости. Локально задайте переменные окружения `TDESKTOP_API_ID` и `TDESKTOP_API_HASH`, затем запустите сборку **без** `-TestApi`.

`scripts/api-cache.cmake` считывает значения из окружения: они не передаются аргументами процесса. CMake хранит их в локальном игнорируемом `out/`; не публикуйте build directory, диагностический архив или лог, содержащий реквизиты.

## Работа вдвоём

1. Оба получают одинаковую `main` и проверяют Debug-сборку.
2. Согласовывают первую функцию, владельца и список файлов.
3. Каждый работает в отдельной копии и назначенной ветке по `AGENTS.md`.
4. Небольшой pull request проверяет второй разработчик; объединение — после относящихся к задаче проверок.
